操作原理 · method

M-31產生單檔教材頁，圖片以 data URI 內嵌

教材原始碼寫在 page_src.html，圖片位置用 {{FIG:名稱｜圖說}} 標記；build_page.py 把標記換成內嵌圖片，產生自足的 index.html。

教材頁要能「雙擊就開、寄給別人也能看」，所以不能有外部相依。但原圖動輒 2–4 MB，直接內嵌會讓頁面過大——所以先縮到網頁尺寸、轉成 WebP（品質 80）再以 data URI 內嵌，六張圖合計約 0.9 MB。縮圖存在 _web/ 當快取，可以安全刪除後重跑。

im = Image.open(src)
im = im.resize((w, round(im.height * w / im.width)), Image.LANCZOS)
im.save(dst, 'WEBP', quality=80, method=6)
b64 = base64.b64encode(dst.read_bytes()).decode('ascii')
html = f'<img src="data:image/webp;base64,{b64}">'
← 可左右滑動 →

展開後要檢查有沒有漏掉的標記：build_page.py 在還找得到 {{ 時會直接中止，不會靜默產出一頁少了圖的教材。另外縮圖快取要比對修改時間（dst.stat().st_mtime < src.stat().st_mtime），不然換了原圖也不會重做。

M-32發布版把影片內嵌成 data URI

build_artifact.py 產生發布用的 artifact_body.html：去掉 HTML 外殼，並把影片換成內嵌的 data URI。

私有 Artifact 的 CSP 會擋外部主機，所以 iframe 播放器載不出來。EP1-1 的影片在 YouTube，所以那邊是把 iframe 換成一張連往 YouTube 的連結卡（連結是導航，不是載資源，不受 CSP 影響）。EP1-2 的影片還沒公開，沒有外部網址可連，所以改成整個內嵌：data URI 屬於頁面自己的內容，不受 CSP 阻擋。母帶 1920×1080 有 51 MB，base64 之後會超過 16 MB 上限，所以內嵌的是 960×540 VP9 的 web 版（5.8 MB → base64 7.7 MB）。

b64 = base64.b64encode(WEBM.read_bytes()).decode('ascii')
assert len(b64) < 16 * 1024 * 1024, 'base64 之後超過 Artifact 上限'
html = f'<video controls src="data:video/webm;base64,{b64}"></video>'
← 可左右滑動 →

base64 會膨脹 4/3，估上限時要用膨脹後的大小。build_artifact.py 在超過時直接報錯，不會靜默產出壞頁面。還有一個相反方向的坑：這個內嵌只適用於 Artifact。教材搬上公開網站時，本機相對路徑的影片在網站上不存在，網站產生器會把播放器換成「尚未上架」的佔位卡。之後影片上架 YouTube，再把這段改回 EP1-1 的連結卡做法即可。
