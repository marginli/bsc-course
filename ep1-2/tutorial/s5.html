5哪一顆不對勁——以及「你為什麼這樣覺得」

使用者發言的五種顏色🟢 請求動作🔵 問問題🟣 關鍵決策 / 概念提問🟡 中斷 / 踩剎車🔴 設計回饋 / 要求自我審視（「有沒有哪一顆不對勁？說明你為什麼這樣覺得」）。完整說明 →
🔴 使用者：這張圖版有沒有哪一顆看起來不對勁？列出來，並說明你為什麼覺得不對勁。

後半句才是重點。「為什麼」逼著 AI 把「看起來怪怪的」換成可以查的量——四個指標：3D 連通元件、局部半徑（距離變換）、飽和比例、碎片與本體的強度對比。

「操作原理」（四個欄位，點一下展開）——不寫程式的話整段可以跳過。

操作原理 · method

M-2126-連通元件標記

把「亮度 > 0」的體素依 3D 相鄰關係分群，數出總共有幾塊。

連通元件標記走訪整個布林體積，把彼此相鄰的前景體素標成同一個編號。相鄰怎麼定義是一個選擇：3D 上有 6-連通（只算面貼面）、18-連通（加上邊）、26-連通（加上角，也就是 3×3×3 立方體裡除了自己以外全算）。這裡用 26-連通，也就是 structure=np.ones((3,3,3))——最寬鬆的定義，所以算出來的碎片數是下界：連 26-連通都連不起來，那是真的斷開了。

from scipy import ndimage
b = vol > 0
lab, ncomp = ndimage.label(b, structure=np.ones((3, 3, 3)))   # 26-連通
sizes = np.bincount(lab.ravel()); sizes[0] = 0    # 0 是背景，要排除
← 可左右滑動 →

ndimage.label 的預設結構是 6-連通，不寫 structure 會得到更多碎片，而且那些碎片可能只是斜著相鄰。np.bincount 的第 0 格是背景，一定要歸零再找最大，否則 argmax 永遠指到背景。

M-22主元件與碎片

把最大的元件當作神經元本體，其餘全部歸為碎片，算出碎片佔訊號的比例。

「一顆神經元理論上應該是一塊」是這個指標的前提。取最大元件當本體是務實的做法——它通常佔九成以上。比例的分母是訊號體素總數（b.sum()），不是整個立體的體素數，否則 0.85% 的非零比例會把所有數字稀釋成零點幾。實測：

碎片多不等於異常。 這一集判定這四顆是訊噪比與閾值造成的斷裂，不是形態差異，也不是繪製錯誤——判準是碎片離本體很近（見 M-23）而且比本體暗（見 M-27）。單看元件數會得到相反的結論：fru-F-900054 只有 1 個元件、0 個碎片，反而是最可疑的那一顆。

操作原理 · method

M-24局部半徑：這條神經在這裡有多粗

對前景做距離變換，取所有訊號體素上的中位數與第 95 百分位。

同一個 EDT，極性反過來餵：對 b（訊號）做，得到的是「每個訊號體素離背景多遠」，也就是這根神經在這個位置的半徑。中位數描述典型粗細，p95 描述最粗的地方。實測 19 檔的中位數全部是 1.00 µm，只有 fru-F-900054 是 1.41；p95 其餘檔是 1.73–3.00，它是 4.12。「比較粗」還可以說是生物差異，但配上其他三個指標就不行了。

radius = ndimage.distance_transform_edt(b)[b]
print(np.median(radius), np.percentile(radius, 95))
← 可左右滑動 →

[b] 這個遮罩不能省——不遮的話背景的 0 會佔九成九，中位數直接變 0。另外這是「內切球半徑」不是解剖學上的直徑，拿來跨檔比較可以，拿來當生物量測不行。

M-25飽和比例與中位強度／上限

算「頂到該檔強度上限的體素佔訊號的比例」，以及「訊號中位數 ÷ 上限」。

這兩個都是相對於該檔自己的上限，所以 255 組與 4095 組可以放在一起比。飽和比例高代表大量體素被截頂——真實的螢光影像不會這樣；中位／上限高代表整體偏亮。實測 fru-F-900054 的飽和比例是 4.26%（其餘 ≤ 1.19%）、中位／上限 0.347（其餘 0.038–0.176）。

sat = 100 * (vol == vol.max()).sum() / b.sum()
med_over_ceil = np.median(vol[b]) / vol.max()

vol == vol.max() 用的是該檔自己的最大值，不是型別上限 65535。寫死 65535 的話，上限只到 255 的那 5 檔會全部算出 0%，看起來完美無缺。分母同樣是訊號體素數，不是全部體素數。

🔄 AI 的第三個錯（也是被推翻的結論）：拿質心當基準

AI 一開始說：VGlut-F-600670 的碎片「離主元件質心 445–516 µm，所以這張影像裡混進了另一顆細胞」。這是錯的。

把它畫出來才看到：碎片是交錯散布在同樣那兩叢分支內部的。這顆神經元橫跨 836 µm，質心落在兩叢中間的空白處，所以任何在分支裡的東西離質心都有 400 µm 以上。那個數字是幾何假象。

錯的量法
碎片到主元件質心的距離
445–516 µm
→ 誤判成「另一顆細胞」
對的量法
碎片到主元件最近體素的距離
中位 13.6 µm，最遠 90 µm
→ 正解：暗的細分支被閾值切斷

佐證：碎片的強度中位數一律只有本體的一半左右（11 vs 17、269 vs 558、239 vs 490），而破碎最嚴重的幾顆正好是非零比例最低（訊號最弱）的幾顆。

操作原理 · method

M-23距離變換：碎片離本體多遠

對「本體以外」做歐氏距離變換，得到每個位置離本體最近的距離，再取碎片位置上的中位數與最大值。

歐氏距離變換（EDT）對一個布林陣列算出「每個 True 位置離最近的 False 有多遠」。所以要量「離本體多遠」，輸入要餵 ~body——這樣 False 就是本體，算出來的距離是「離本體多遠」。體素是 1 µm 等向，所以距離的單位直接就是 µm，不必再換算。

dist = ndimage.distance_transform_edt(~body)   # 注意是 ~body
print(np.median(dist[frag]), dist[frag].max())  # 13.6 µm / 90 µm
← 可左右滑動 →

餵錯極性（傳 body 而不是 ~body）不會報錯，只會得到「離背景多遠」——那是 M-24 的局部半徑，完全不同的量。體素若不是等向，distance_transform_edt 要傳 sampling=(dz, dy, dx)，否則距離是格數不是長度。這一集剛好等向，所以省得掉。

M-26質心距離為什麼會騙人

把「碎片離主元件質心多遠」換成「碎片離最近的本體體素多遠」，結論反轉。

AI 一開始說：VGlut-F-600670 的碎片「離主元件質心 445–516 µm，所以這張影像裡混進了另一顆細胞」。這是錯的。質心是所有訊號點的座標平均，不保證落在實體上。這顆神經元橫跨 836 µm、左右兩叢中間是空的，質心正好落在中間那塊空白處，於是任何在分支裡的東西離質心都有 400 µm 以上——那是幾何假象。換成「離最近的本體體素多遠」（M-23）之後：中位 13.6 µm、最遠 90 µm，正解是暗的細分支被閾值切斷。

量法得到的數字推出的結論

碎片到最近的本體體素中位 13.6 µm，最遠 90 µm暗的細分支被閾值切斷

print(body[tuple(cen.round().astype(int))])       # 常常是 False

發現這件事的方法是把它畫出來。 光看數字（445 µm）看不出問題，把碎片標成青色疊在本體上，一眼就看到碎片是交錯散布在兩叢分支內部的。這是這一集第二個「靠對照抓到的錯」（另一個是 M-16）。通則：下結論前換一個量法再驗一次，並且先問這個量法有沒有幾何假象。

操作原理 · method

M-27碎片與本體的強度對比

比較碎片與本體各自的強度中位數。

如果碎片是「被閾值切斷的暗分支」，它們應該比本體暗；如果是「別的構造被一起框進來」，就沒有理由比較暗。實測那四顆破碎的檔案，碎片強度中位數一律只有本體的一半左右（11 vs 17、269 vs 558、239 vs 490），而且破碎最嚴重的幾顆正好是非零比例最低（訊號最弱）的幾顆——兩條獨立的線索指向同一個解釋。

反例也有：Trh-F-300000 乾淨得不像同一批（只有 2 個元件），但那唯一的碎片有 7,922 個體素、強度中位 286，高於本體的 265。其餘各檔的碎片一律比本體暗，只有這顆反過來。此顆未能定論，已列入待查事項。

print(int(np.median(vol[frag])), int(np.median(vol[body])))
← 可左右滑動 →

用中位數不要用平均——碎片數量少、又常含極端值。另外「比本體暗」是線索不是判決：染色的神經元附近本來就可能有斷掉的細突起，影像雜訊也會產生小碎片。要合起來看大小、距離與強度三件事。

異常 3：Trh-F-300000——反方向的怪

它乾淨得不像同一批（只有 2 個元件），但那唯一的碎片有 7,922 個體素、強度中位 286，高於本體的 265。其餘各檔的碎片一律比本體暗，只有這顆反過來。一塊比本體還亮的大團塊脫離在旁邊，比較像是另一個結構被一起框進來。此顆未能定論，已列入報告的待查事項。

看起來怪但其實沒問題的

  • Gad1-F-400376：兩葉對稱、俯視圖是一條直棒。那是因為它真的很扁——z 只有 117 µm，20 顆裡最薄。形狀正常。
  • 一個被資料否定的猜測：AI 原本預期 EP1-1 那 5 個「上限 255」的檔會比較破碎。結果 TH-F-100051 屬於那組，卻是 20 顆裡最完整的（主元件 100.0%）。量化深度與破碎程度沒有相關性。

還有一個被作廢的指標：AI 曾試著用「二值侵蝕兩次後存活的緻密團塊」找胞體，但密集分支叢同樣存活（TH-F-100051 得到 10,799 體素的團塊），無法區分胞體與分支叢。這個指標沒有用於任何結論，但過程保留在報告裡——試過但不管用的方法也是資訊。

操作原理 · method

M-28二值侵蝕找胞體（試過，作廢）

把訊號區域從邊緣往內削兩層，想留下「比較粗的那一團」＝胞體。

二值侵蝕（binary erosion）會讓細的結構先消失、粗的結構留下，所以理論上侵蝕兩次之後活下來的緻密團塊就是胞體。實測不管用：密集的分支叢同樣存活——TH-F-100051 侵蝕後得到一個 10,799 體素的團塊，但那不是胞體，是分支叢。這個指標沒有用於任何結論，過程保留在報告裡。

core = ndimage.binary_erosion(b, np.ones((3, 3, 3)), iterations=2)
print(int(core.sum()))     # TH-F-100051：10,799，但不是胞體
← 可左右滑動 →

試過但不管用的方法也是資訊，要寫進報告——否則下一個人會再試一次。侵蝕失敗的原因值得記住：它分不出「一根粗的」與「很多根細的擠在一起」，因為兩者的局部半徑分布在這個尺度上重疊。要分開得換方法（例如骨架化）。
