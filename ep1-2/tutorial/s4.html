🟢 使用者：把 20 顆都畫出來，排成一張圖版，每一格標上檔名。

到這裡才批次處理——前面三輪已經把畫法的每個選擇都驗過一遍了。兩條不能違反的規則：

  1. 全圖版共用同一比例尺（1 px = 1 µm），格子大小取全體最大者、神經元置中不縮放。各檔寬度差 5.5 倍，若讓每格各自縮放填滿，小的會被放大成跟大的一樣。
  2. 亮度各格自行正規化，因此跨格不可比。EP1-1 查出的那 5 個上限 255 的檔，硬套同一窗位會整片過曝；圖版上以 ● 標出這 5 檔。實際用到的 gamma 從 0.32 到 1.80 都有。

    3. 「操作原理」（四個欄位，點一下展開）——不寫程式的話整段可以跳過。

    操作原理 · method

    M-18圖版共用比例尺：格子取全體最大、置中、不縮放

    所有格子同一個 px/µm（1 px = 1 µm），格子大小取全體最大者，每顆神經元置中貼上，不縮放。

    20 個檔各自裁到自己的 bounding box，寬度從 153 µm 到 842 µm、差 5.5 倍。若讓每格各自縮放填滿，小的會被放大成跟大的一樣——那是最容易騙人的畫法，而且看圖的人完全察覺不到。固定 px/µm 之後，格子裡的大小就是真實大小，代價是小的那幾顆周圍留白很多。留白是誠實的代價，不是缺點。

    cell_w = max(i['dims'][0] for i in items)   # 全體最大
cell_h = max(i['dims'][1] for i in items)
cell = Image.new('RGB', (cell_w, cell_h), (0, 0, 0))
cell.paste(im, ((cell_w - im.width) // 2, (cell_h - im.height) // 2))

    「畫得下」和「讀得懂」是兩件事。同一支程式也產了一張每格三視圖的版本（plate.py three），20 顆 × 3 視角在一張圖上會擠，所以預設仍是單視圖。比例尺也只畫一根並註明「全圖版適用」——每格畫一根會讓人以為各格不同尺。

    M-19各格自行正規化，並把不可比寫在圖上

    亮度每格自己算窗位與 gamma（規則同 M-09、M-10），然後在圖上明講「亮度跨格不可比」，並把上限只有 255 的 5 個檔標出來。

    EP1-1 查出 5 個檔的強度上限只到 255、其餘 15 檔到 4095。硬套同一個窗位，那 5 顆會整片過曝。所以這裡故意讓亮度不可比，換取形態可比——但這個取捨必須寫在圖上，否則讀者會拿亮度下結論。實際用到的 gamma 從 0.32 到 1.80 都有。

    tag = '　● 上限 255' if item['ceiling'] <= 255 else ''
draw.text((x, y + 25), f"{nx}×{ny}×{nz} µm　gamma {g:.2f}{tag}",
          fill=(214, 148, 60) if tag else DIM)

    圖版一畫出來就看得到：標 ● 的 5 顆看不出跟其他 15 顆有什麼不同。量化深度的差別體現在灰階層次，不在形態，正規化之後就被吸收掉了。這也否定了一個當時的猜測——AI 原本預期那 5 個檔會比較破碎，結果 TH-F-100051 屬於那組，卻是 20 顆裡最完整的（主元件 100.0%）。

圖版一畫出來，有幾件事是單看一顆時看不到的：

  • 六顆 Tdc2 裡有五顆（000022、000026、100067、200065、200066）形態高度一致：左側小叢、右側大扇、中間一條長軸突。剩下的 Tdc2-F-000001 不屬於這個模子——它是左右對稱的兩叢，沒有那條長軸突。同品系不等於同形態，所以這種視覺交叉驗證要指名是哪幾顆，不能整組帶過。
  • 標 ● 的 5 顆看不出跟其他 15 顆有什麼不同——量化深度的差別體現在灰階層次，不在形態，正規化之後就被吸收掉了。
  • Trh-F-600017、VGlut-F-300388/600670 的俯視圖顯示它們幾乎是平的一層，這在正視圖完全看不出來——正好是上一段那個「換方向就變另一個形狀」的現成例子。
  • fru-F-900054 的 gamma 撞到上限 1.80 仍然偏亮、細節糊成一片。這是下一段的伏筆。

同一支程式也產了一張每格三視圖的版本（plate.py three）。20 顆 × 3 視角在一張圖上會擠，所以預設仍是單視圖——「畫得下」和「讀得懂」是兩件事。

操作原理 · method

M-20排序與分組

檔名依「品系（不分大小寫）→ 完整編號」排序，同品系因此排在一起。

排序看起來只是版面問題，其實是免費的交叉驗證：同品系同類的神經元形態應該相似，排在一起一眼就比得出來。這一集六顆 Tdc2 裡有五顆形態高度一致（左側小叢、右側大扇、中間一條長軸突），那等於用視覺確認了讀檔與繪製流程沒有系統性錯誤。剩下的 Tdc2-F-000001 明顯不同——同品系不等於同形態。

def sort_key(path):
    stem = path.name.replace(SUFFIX, '')
    return (stem.split('-')[0].lower(), stem)   # 品系優先，大小寫不分

直接用檔名字串排序會把大小寫不同的品系拆開（TH- 與 Tdc2- 在 ASCII 裡差很遠）。分組的價值就在於「同一組排在一起」，拆開就沒了。
