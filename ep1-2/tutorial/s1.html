操作原理 · method

M-01先掃過 20 檔的中繼資料，還沒有畫圖

讀出每個檔的維度、體素尺寸、強度上限與非零比例。這一步決定了後面兩件事：體素是 1 µm 等向（20/20），所以三視圖不需要非等向縮放；各檔寬度從 153 µm 到 842 µm、差 5.5 倍，所以排圖版時一定要強制共用比例尺。

「先只畫一顆」是使用者踩的剎車，但 AI 連一顆都還沒畫——先問尺度。維度與體素尺寸來自檔頭，不必解壓；強度上限與非零比例要解壓才知道，但只是兩個 numpy 歸約，20 個檔幾秒鐘。尺度沒摸清楚就畫圖，畫出來的每個決定都是猜的。

for path in sorted(SRC.glob('*.am')):
    vol, meta = read_am(path)
    print(meta['dims'], voxel_size(meta), int(vol.max()),
          f"{100 * (vol > 0).mean():.2f}%")
← 可左右滑動 →

非零比例要用 (vol > 0).mean()，不是 vol.mean()——後者是平均強度，是完全不同的東西。這一集非零比例只有 0.85%，這個數字後面決定了「旋轉投影用點雲而不是內插整個陣列」（見 M-13）。

M-02把 .am 解成 numpy 陣列

找到資料段、zlib 解壓、依宣告的型別與端序解讀成整數、reshape 成 (nz, ny, nx) 的三維陣列。

檔頭是純文字，用標記 # Data section follows\n 切開；資料段開頭是 @1\n 標籤，之後才是 zlib 串流。型別 ushort 對應 np.uint16，端序由檔頭的 BINARY-LITTLE-ENDIAN 決定，所以 dtype 要寫成 np.dtype(np.uint16).newbyteorder('<')。reshape 的順序是 (nz, ny, nx)——x 變動最快，與 Amira 的 lattice 排列一致。格式本身怎麼判讀出來的，見 EP1-1。

raw = open(path, 'rb').read()
i = raw.find(b'# Data section follows\n')
header, body = raw[:i].decode('latin-1'), raw[i + 23:]
payload = body[re.match(rb'\s*@1\n', body).end():]
blob = zlib.decompress(payload[:nbytes])
vol = np.frombuffer(blob, dtype=np.dtype('<u2')).reshape((nz, ny, nx))
← 可左右滑動 →

解出來的長度一定要檢查：len(blob) == nx*ny*nz*itemsize。reshape 排錯不會報錯（只要總數對得上），只會安靜地給你一個錯的形狀——EP1-1 那張「排錯就變條紋」的對照圖就是這件事。另外 np.frombuffer 回傳的是唯讀 view，要改值得先 .copy()。

M-03由 BoundingBox 算體素尺寸

把檔頭的 BoundingBox（六個座標）與維度換算成一個體素在真實空間有多大。

Amira 的 uniform BoundingBox 標的是體素中心的範圍，不是外緣。所以 n 個體素之間只有 n−1 個間隔，體素尺寸是 (max − min) / (N − 1)，不是 / N。這一集 20 個檔算出來全部是 1 µm 等向，所以三個軸的比例是 1:1:1，三視圖直接畫就對齊，不必做非等向縮放。

xmin, xmax, ymin, ymax, zmin, zmax = bbox
dx = (xmax - xmin) / max(nx - 1, 1)     # N-1：BoundingBox 標的是體素中心
dy = (ymax - ymin) / max(ny - 1, 1)
dz = (zmax - zmin) / max(nz - 1, 1)
← 可左右滑動 →

除以 N 而不是 N−1 會得到一個接近但不對的值，維度越小誤差越大（161 個體素差 0.6%，10 個體素就差 10%）。這種錯不會讓圖看起來壞掉，只會讓比例尺與長度標註全部偏一點——沒有對照就發現不了。另外 max(N-1, 1) 是防單層資料除以零。

選的樣本是 Tdc2-F-000022：

選它Tdc2-F-000022　500×312×215 µm，強度上限 4095非零體素 0.85%
理由一屬於正常的 15 檔那組，避開 EP1-1 查出、上限只有 255 的 5 檔
理由二形態橫跨兩側，有明顯主幹與兩團分支，三個視角都看得出東西

這張圖裡有三個決策，每一個都有理由：

決定理由
三面板共用同一比例尺（1 px = 0.5 µm）否則會出現「側面看起來比較胖」這種純粹由縮放造成的錯覺
三面板共用同一窗位與 gamma同一顆的三個視角要互相可比；跨檔則不可比，因為各檔強度上限不同
gamma 由投影訊號中位數自動決定EP1-1 已查出強度上限有 255 與 4095 兩組，固定窗位會讓其中一組全毀

操作原理 · method

M-04三個互相垂直的最大強度投影

把 (z, y, x) 的立體沿三個軸各取一次最大值，得到正視、側視、俯視三個平面。

投影就是沿一條軸做歸約。陣列軸順序是 (z, y, x)，所以：

視圖算式結果形狀橫軸／縱軸
正視 frontvol.max(axis=0)(ny, nx)x ／ y
側視 sidevol.max(axis=2).T(ny, nz)z ／ y
俯視 topvol.max(axis=1)(nz, nx)x ／ z

側視要多一個 .T：沿 x 投影得到的是 (nz, ny)，轉置成 (ny, nz) 之後縱軸才是 y——正視與側視共用縱軸，正視與俯視共用橫軸，三個面板因此可以對齊著看。這是工程製圖的標準排法。

planes = {
    'front': vol.max(axis=0),
    'side':  vol.max(axis=2).T,   # 轉置後縱軸才是 y
    'top':   vol.max(axis=1),
}
← 可左右滑動 →

軸編號很容易寫反。驗證方法：三個平面的形狀必須兩兩共用一個邊長（正視 (ny,nx) 與側視 (ny,nz) 共用 ny，正視與俯視 (nz,nx) 共用 nx）。對不上就是軸弄錯了，而圖看起來一樣有東西。

M-05三面板共用比例尺與對齊

三個面板用同一個 px/µm，畫布按真實維度配置，一根比例尺標全圖。

體素既然是 1 µm 等向，只要每個體素固定畫成 SCALE×SCALE 像素（這一集 SCALE=2，也就是 1 px = 0.5 µm），三個面板就自動同尺。放大用 Image.NEAREST 而不是雙線性——放大要看見體素本身，不要製造資料裡沒有的中間值。比例尺長度是算出來的：bar_px = round(100 * SCALE / vx)。

im = im.resize((im.width * SCALE, im.height * SCALE), Image.NEAREST)
bar_px = int(round(100 * SCALE / vx))      # 100 µm 比例尺
draw.line([x, y, x + bar_px, y], fill=FG, width=4)
← 可左右滑動 →

各面板各自縮放填滿版面是最容易騙人的畫法——側視圖會看起來比較胖，而那個「胖」完全是縮放造成的。這一集三個面板的實際尺寸是 500×312×215 µm，差異必須留在圖上。

M-06色階：把數字對應成顏色

用一條八個停駐點的色階（黑 → 暗紫 → 洋紅 → 橘 → 近白）把 0–1 的正規化強度轉成 RGB，中間線性內插。

查表加內插：把正規化值乘上「停駐點數 − 1」得到浮點位置，整數部分挑出前後兩個停駐點，小數部分當混合權重。這條色階刻意讓亮度單調遞增，所以強度仍然讀得出來；但暗處抬得比灰階高很多，細的神經突起不會沉進背景。

norm = np.clip(plane / vmax, 0, 1) ** gamma
pos = norm * (len(RAMP) - 1)
idx = np.clip(pos.astype(np.int32), 0, len(RAMP) - 2)
frac = (pos - idx)[..., None]
rgb = RAMP[idx] * (1 - frac) + RAMP[idx + 1] * frac
← 可左右滑動 →

科學影像的色階必須亮度單調。彩虹色階（jet）在中段有亮度反轉，會憑空製造出看起來像邊界的東西，這是視覺化領域公認的地雷。另外 idx 要 clip 到 len(RAMP) - 2，不然 norm 剛好等於 1 時 RAMP[idx + 1] 會越界。

M-07自動 gamma：用中位數定位，不用峰值

解一個 gamma，讓「投影後所有非零像素的中位數」落在畫面亮度的 0.60。

gamma 校正是 `out = in gamma。要讓正規化中位數 m 顯示成 0.60，解 m g = 0.60` 得到 g = ln(0.60) / ln(m)，再夾到允許範圍。用中位數而不是平均或峰值，是因為中位數不受少數極亮點影響（見 M-09）。這一集不用固定窗位，正是因為 EP1-1 已查出強度上限有 255 與 4095 兩組——固定窗位會讓其中一組整片全毀。

signal = np.concatenate([p[p > 0].ravel() for p in planes])
median = float(np.median(signal)) / vmax
gamma = np.clip(np.log(0.60) / np.log(median), 0.55, 1.80)
← 可左右滑動 →

只取非零像素算中位數。把整片背景的 0 算進去，中位數會直接變成 0，log(0) 就爆了。夾住上下限也是必要的：median 極小時 gamma 會趨近 0，整張圖被提亮成一片白——這一集 fru-F-900054 就撞到上限 1.80 仍然偏亮，而那正是它被列為異常的第一個線索。

當時沒解決、現在仍然沒解決的一點：縱向是照陣列列序畫的（第 0 列在上），解剖學上的背腹前後沒有核對過。圖上有註明，報告的「未驗證事項」也列著。做不到的事要講出來，不要假裝圖上的方向有意義。
